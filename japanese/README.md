# NDS実機・melonDS向け エラーコード 86420 対処法まとめ

## 結論

エラーコード `86420` は、ざっくり言うと **相手プレイヤーとの通信経路を作れない** ときに出やすいエラーです。

サーバーへのログインそのものではなく、対戦・合流・フレンド接続など、相手との通信が必要になる場面で発生しやすいです。

中心原因は **NAT**、**UDP通信の遮断**、**ファイアウォール**、**CGNAT**、**ホットスポット/テザリングの制限** です。

任天堂系の説明としては、`86420` は「自分または相手側の通信環境にあるNAT機能が原因で接続できない」系のエラーとして扱われます。つまり、自分側だけが悪いとは限らず、相手側のNATでも発生します。

---

## 86420の意味

`86420` は、次のような状態を指します。

```text
サーバー接続: 成功する場合がある
Wi-Fi接続テスト: 成功する場合がある
フレンドリスト/ログイン: 成功する場合がある
対戦・合流: 失敗する
結果: 86420
```

重要なのは、**サーバーと通信できること** と **相手プレイヤーと通信できること** は別物という点です。

NDS Wi-Fi系の通信では、ゲームや機能によってはサーバー中心の通信だけで済む場面があります。逆に、対戦・合流のような場面では、相手とのP2Pに近い通信経路が必要になることがあります。

そのため、次のような症状は普通に起こります。

```text
ランキングや一部サーバー機能は使える
しかし、直接対戦や合流だけ86420で失敗する
```

この場合、DNSだけを見ても解決しないことが多いです。

---

## NATとは何か

NATは、簡単に言うと **家庭内やスマホ回線内のプライベートIPアドレスを、インターネット側のグローバルIPアドレスに変換する仕組み** です。

例:

```text
NDS / PC / スマホ
  ↓
192.168.x.x などのプライベートIP
  ↓ NAT変換
グローバルIP
  ↓
インターネット
```

普通のWeb閲覧や動画視聴では、内側から外へ通信を始めるだけなので問題になりにくいです。

しかし、NDSの対戦・合流のように、相手側から戻ってくるUDP通信を受ける必要がある場合、NATの種類によっては通信経路を作れません。

このときに `86420` が出やすくなります。

---

## 86420の主な原因

| 原因 | 内容 | 実機NDS | melonDS |
| --- | --- | --- | --- |
| Strict NAT | 相手からのUDP通信が戻ってこない | あり | あり |
| UDP遮断 | ルーターや回線側でUDPが制限される | あり | あり |
| UPnP無効 | 自動ポート開放が働かない | あり | あり |
| ポート開放先ミス | 固定IPが変わっていて別端末へ転送される | あり | あり |
| Windowsファイアウォール | melonDS.exeの通信が遮断される | なし | あり |
| 二重ルーター | ルーターが2段になって外から届かない | あり | あり |
| CGNAT | ISP/モバイル回線側でさらにNATされる | あり | あり |
| ホットスポット | 端末に外部から直接届かない | あり | あり |
| 相手側NAT | 自分側が正常でも相手側で失敗する | あり | あり |

---

## 最初に見るべきポイント

優先順位はこの順番です。

1. 同じゲーム・同じサーバー環境で接続しているか確認する
2. Wi-Fi接続テストが通るか確認する
3. ルーターのUPnPをONにする
4. 実機NDSまたはmelonDSを動かすPCのローカルIPを固定する
5. melonDSの場合、Windowsファイアウォールで `melonDS.exe` を許可する
6. 二重ルーターになっていないか確認する
7. ルーターのWAN側IPがグローバルIPか確認する
8. DMZまたはポート開放でNAT/UDPが原因か切り分ける
9. ホットスポットではなく固定回線で試す
10. 別の相手でも同じエラーが出るか確認する

```text
  └─ はい
       ↓

  ├─ いいえ → DNS / サーバー設定 / firmware設定を確認
  └─ はい
       ↓
対戦・合流だけ失敗する？
  ├─ いいえ → 別原因の可能性
  └─ はい
       ↓
melonDS？
  ├─ はい → Windowsファイアウォール、PC固定IP、UPnP、VPNを確認
  └─ いいえ → NDS固定IP、UPnP、DMZ、ルーターNATを確認
       ↓

  └─ いいえ
       ↓

  └─ いいえ → 自分側ルーター / 回線 / サーバー設定を再確認
```

## フローチャートの読み方

`86420` は、接続テストやサーバーログインが成功していても、対戦・交換・合流の段階で発生することがあります。

その場合はDNSだけではなく、UDP通信、NAT、UPnP、DMZ、CGNAT、相手側NATを順番に見るのが効率的です。

# 実機NDS向け

## 1. まず接続テストを通す

実機NDSでは、まずゲーム内または本体側のWi-Fi設定で接続テストが成功する必要があります。

確認項目:

- NDSが接続できるアクセスポイントを使っている
- 2.4GHz帯を使っている
- NDSが対応できる暗号化方式を使っている
- DNS設定が使用中のWFC/Wiimmfi系サーバーに合っている
- IPアドレス、サブネットマスク、ゲートウェイが正しい
- アクセスポイント側で古い機器の接続が拒否されていない

ただし、接続テスト成功は `86420` 解決の証明にはなりません。

接続テストは主に「サーバーへ出ていけるか」を見るもので、相手プレイヤーとのUDP通信が成立するかまでは保証しません。

---

## 2. NDSのローカルIPを固定する

ポート開放やDMZを試す場合、NDSのIPアドレスが変わると設定が無効になります。

ルーター側のDHCP固定割り当て、またはNDS側の手動設定でIPを固定します。

例:

```text
NDS IP Address: 192.168.1.50
Subnet Mask:    255.255.255.0
Gateway:        192.168.1.1
Primary DNS:    使用するWFC/Wiimmfi系DNS
Secondary DNS:  必要に応じて設定
```

ルーターのDHCP配布範囲と被らないIPにすると安全です。

例:

```text
ルーターのDHCP範囲: 192.168.1.100 ～ 192.168.1.200
NDSに固定するIP:    192.168.1.50
```

---

## 3. UPnPをONにする

ルーターがUPnPに対応している場合、自動で通信経路を作れることがあります。

ルーター設定画面で次のような項目を探します。

```text
UPnP
Universal Plug and Play
UPnP IGD
自動ポート開放
```

ONにしたあと、NDSを再接続して、対戦・合流を試します。

UPnPで改善する場合、手動ポート開放より簡単です。

ただし、ルーターや回線によってはUPnPが効かないこともあります。

---

## 4. DMZで切り分ける

NDSの固定IPをDMZに入れると、外部から届く通信を広くNDSへ送ることができます。

例:

```text
DMZ Host: 192.168.1.50
```

DMZで `86420` が改善するなら、原因はかなり高い確率でNAT/UDP/ポート周りです。

改善した場合に考えられる原因:

- ポート開放が足りていなかった
- ポート開放先IPが間違っていた
- UDPが遮断されていた
- UPnPが正常に働いていなかった

DMZでも改善しない場合に考えられる原因:

- CGNAT配下にいる
- 二重ルーターになっている
- ホットスポット側で外部からの通信を受けられない
- 相手側のNATで失敗している
- サーバー/ゲーム/対戦相手との相性

DMZは原因切り分けとしては強いですが、常用するより、改善するかどうかを確認するためのテストとして使うのが無難です。

---

## 5. 二重ルーターを確認する

二重ルーター構成だと、NDS側のルーターだけ設定しても外から届きません。

よくある構成:

```text
インターネット
  ↓
ONU / ホームゲートウェイ
  ↓
市販ルーター
  ↓
NDS
```

この場合、NATが2段になります。

確認方法:

1. 市販ルーターのWAN側IPを見る
2. そのIPが `192.168.x.x`、`172.16.x.x～172.31.x.x`、`10.x.x.x` のようなプライベートIPなら二重ルーターの可能性が高い
3. 上流側のONU/ホームゲートウェイでもNATが有効になっていないか確認する

対処方針:

- どちらか片方をブリッジ/APモードにする
- ポート開放を上流と下流の両方で設定する
- NDS側ルーターを上流ルーターのDMZ先にする

---

## 6. CGNATか確認する

CGNATは、家庭のルーターよりさらに外側、回線事業者側でNATされている状態です。

この場合、自宅ルーターでポート開放やDMZを設定しても、外部からの通信が届かないことがあります。

確認方法:

1. ルーターの管理画面でWAN側IPを見る
2. ブラウザで表示される自分のグローバルIPと比較する
3. 両方が違う場合、CGNATの可能性がある
4. WAN側IPが `100.64.0.0～100.127.255.255` の範囲ならCGNATの可能性が高い
5. WAN側IPが `10.x.x.x`、`172.16.x.x～172.31.x.x`、`192.168.x.x` なら、上流にNATがある

CGNATだと、実機NDS側でできることはかなり減ります。

この場合は、固定回線、グローバルIPが割り当てられる回線、またはポートフォワード可能なネットワークへ変える方が効果的です。

# melonDS向け

## 1. melonDSではPC側のネットワークも見る

melonDSの場合、NDS本体ではなくPC上で通信するため、実機NDSのチェックに加えてPC側の設定も重要になります。

主に見る場所:

- Windowsファイアウォール
- セキュリティソフト
- PCのローカルIP
- ルーターのUPnP
- ルーターのポート開放/DMZ
- VPNの有無
- ホットスポット/テザリングの有無

---

## 2. WindowsファイアウォールでmelonDS.exeを許可する

melonDSでは、Windowsファイアウォールが通信を止めていると `86420` の原因になります。

確認する項目:

```text
Windows セキュリティ
  ↓
ファイアウォールとネットワーク保護
  ↓
ファイアウォールによるアプリケーションの許可
  ↓
melonDS.exe を許可
```

できれば、使用しているネットワーク種別に合わせて許可します。

```text
プライベートネットワーク: 許可
パブリックネットワーク: 必要なら許可
```

ネットワークが「パブリック」扱いになっていると、通信が厳しく制限されることがあります。

自宅回線なら、Windows側で「プライベートネットワーク」にしておく方が通りやすいです。

---

## 3. PCのローカルIPを固定する

melonDSでは、ポート開放やDMZの転送先はNDSではなく **melonDSを起動しているPC** です。

例:

```text
PC IP Address: 192.168.1.60
Subnet Mask:   255.255.255.0
Gateway:       192.168.1.1
```

ルーター側で、PCのMACアドレスに対して固定IPを割り当てる方法が安定です。

---

## 4. ルーター側でUPnPまたはポート開放を試す

melonDSを起動しているPCに対して、UPnPまたはポート開放を試します。

優先順:

1. UPnPをONにする
2. PCのローカルIPを固定する
3. melonDS.exeをファイアウォールで許可する
4. まだ駄目ならDMZで切り分ける
5. DMZで改善したら、必要な範囲だけポート開放へ戻す

`86420` はUDP通信が絡むことが多いため、TCPだけでなくUDP側も見る必要があります。

---

## 5. セキュリティソフトの通信制限を見る

Windows標準ファイアウォールでは許可されていても、別のセキュリティソフトが通信を遮断していることがあります。

確認する項目:

- melonDS.exeがブロックされていないか
- UDP通信が遮断されていないか
- ゲーム/エミュレーターの通信が低信頼アプリ扱いになっていないか
- VPN/プロキシ/通信監視機能が邪魔していないか

一時的に保護を完全に切るのではなく、まずはアプリ単位で `melonDS.exe` を許可するのが安全です。

---

## 6. VPN使用時の注意

VPNは、状況によっては回避策になる場合があります。

ただし、普通のVPNを使えば必ず直るわけではありません。

VPNで改善する可能性があるケース:

- VPN側が外部から到達可能なUDP通信を許可している
- VPN側でポートフォワードが使える
- 相手と同じVPN内にいて、VPN内で直接通信できる
- 自分の通常回線がCGNATで、VPN側の方がNAT条件が良い

VPNで悪化する可能性があるケース:

- VPN側もStrict NAT
- UDPが制限されている
- ポートフォワードが使えない
- 遅延やパケットロスが増える
- melonDS/WFC系通信と相性が悪い

つまり、VPNは「別のネットワーク経路を試す手段」ではありますが、「86420の確実な解決策」ではありません。

---

# ホットスポット/テザリングについて

## 結論: ホットスポットで86420を回避するのは難しいことが多い

スマホのホットスポットやテザリングでは、接続端末にプライベートIPが割り当てられます。

例:

```text
NDS / PC
  ↓
スマホのホットスポット
  ↓
スマホ回線側NAT
  ↓
キャリア側CGNAT
  ↓
インターネット
```

この構成では、外部からNDSやPCへ直接届く通信が遮られやすいです。

特にモバイル回線では、キャリア側でCGNATが使われることが多く、ユーザー側でポート開放できません。

そのため、ホットスポットでは次のような状態になりやすいです。

```text
Wi-Fi接続テスト: 成功
サーバーログイン: 成功
対戦・合流: 86420
```

---

## ホットスポットで試せること

完全に無理とは限りません。

試す価値がある項目:

1. 別のスマホ回線で試す
2. 別のキャリアで試す
3. 5G/4Gを切り替える
4. VPNを使って経路を変える
5. ポートフォワード対応VPNを使う
6. 固定回線のWi-Fiで試す
7. 相手側の回線を変えてもらうのではなく、別の相手との接続結果を比較する

ただし、ホットスポット側でポート開放できない場合、根本的な改善は難しいです。

# MPHの場合

Metroid Prime Huntersの場合、`86420` は自分側だけでなく、相手側のNATでも起きます。

MPHにおいて、`86420` が発生しやすいタイミングは、ランダム対戦のマッチング時と、フレンド／ライバル対戦でホストのロビーに入ろうとしたときです。

つまり、自分の設定がかなり整っていても、相手側がStrict NAT、CGNAT、ホットスポット、UDP制限ありの回線だと失敗することがあります。

MPHでは、次のように考えると分かりやすいです。

```text
自分側NAT: OK
相手側NAT: NG
結果: 86420になる可能性あり
```

```text
自分側NAT: NG
相手側NAT: OK
結果: 86420になる可能性あり
```

```text
自分側NAT: OK
相手側NAT: OK
結果: 接続できる可能性が上がる
```

要するに、MPHの `86420` は「自分の設定だけを直せば必ず消えるエラー」ではありません。

UDP hole punching が、自分、相手、ルーター、回線、サーバー経路のどこかで失敗している状態として見るのが近いです。

# 症状別チェック

## Wi-Fi接続テストは成功するが86420になる

見る場所:

- NAT
- UDP
- UPnP
- ポート開放
- CGNAT
- 相手側NAT

DNSだけを変えても直らないことが多いです。

---

## 一部オンライン機能は使えるが、対戦/合流だけ失敗する

かなり `86420` らしい症状です。

見る場所:

- P2P通信
- UDP hole punching
- ルーターのNATタイプ
- 相手側の通信環境

サーバー型機能が使えることは、直接通信が通る証明にはなりません。

---

## ホットスポットだと失敗する

見る場所:

- スマホ回線側CGNAT
- ホットスポットのNAT制限
- 外部から端末へ到達できない構成
- VPN使用時のUDP/ポートフォワード可否

ホットスポットでは、ユーザー側でルーター設定を変更できないため、固定回線より解決しにくいです。

---

## melonDSだけ失敗する

見る場所:

- Windowsファイアウォール
- セキュリティソフト
- melonDS.exeの許可
- PCのIP固定
- ルーターの転送先がPCになっているか
- VPN/プロキシ
- ネットワーク種別がパブリックになっていないか

---

## 実機NDSだけ失敗する

見る場所:

- NDSが対応できるアクセスポイントか
- DNS設定
- NDSの固定IP
- ルーターのUPnP
- DMZ先がNDSのIPになっているか
- 古いWi-Fi機器の接続制限

---

# 切り分け用の最短手順（簡易版）

最短で原因を絞るなら、次の順番が分かりやすいです。

## 実機NDS

```text
1. 接続テスト成功を確認
2. NDSのIPを固定
3. UPnPをON
4. DMZをNDSのIPに向けて一時テスト
5. ルーターWAN IPとグローバルIPを比較
6. CGNAT/二重ルーターなら回線側の問題として扱う
7. 別の相手で試す
8. ホットスポットではなく固定回線で試す
```

## melonDS

```text
1. melonDS.exeをWindowsファイアウォールで許可
2. PCのIPを固定
3. UPnPをON
4. DMZをPCのIPに向けて一時テスト
5. ルーターWAN IPとグローバルIPを比較
6. VPN/プロキシ/セキュリティソフトを確認
7. 別の相手で試す
8. ホットスポットではなく固定回線で試す
```

# どの状態なら改善見込みが高いか

| 状態 | 改善見込み | 理由 |
| --- | --- | --- |
| 自宅固定回線 + ルーター管理可能 | 高い | UPnP/DMZ/ポート開放を試せる |
| 二重ルーター | 中 | 構成を直せば改善する可能性あり |
| Windowsファイアウォールが原因 | 高い | melonDS.exe許可で改善しやすい |
| 相手側だけStrict NAT | 中～低 | 自分側だけでは完全に直せない |
| CGNAT | 低 | 自宅ルーターでポート開放しても届かない |
| スマホホットスポット | 低 | 外部から端末へ直接届きにくい |
| ポートフォワード対応VPN | 中 | 条件が合えば改善する可能性あり |
| 普通のVPN | 不安定 | VPN側のNAT/UDP制限次第 |

# よくある誤解

## DNSを変えれば86420が直る？

DNSは必要な場合がありますが、`86420` の本体はDNSではないことが多いです。

DNSは接続先サーバーを見つけるための設定です。

相手とのUDP通信やNAT越えを保証するものではありません。

---

## 接続テストが通れば86420は出ない？

出ます。

接続テスト成功は、主にサーバーへ出ていけることの確認です。

P2P通信や相手とのUDP通信が成立するかは別です。

---

## 自分の設定が悪いから86420になる？

そうとは限りません。

86420は、自分側または相手側のNATが原因で起きることがあります。

MPHのような対戦ゲームでは、相手側の回線条件でも発生します。

---

## ホットスポットでも設定すれば直せる？

直せる場合もありますが、難しいことが多いです。

ホットスポットやモバイル回線では、端末側にプライベートIPが割り当てられ、さらにキャリア側CGNATに入ることがあります。

この場合、外部から端末へ直接通信を届ける設定をユーザー側で行えません。

---

# まとめ

`86420` は、単なるDNSミスやサーバー不調ではなく、**相手との通信経路を作れないNAT/UDP系エラー** として見るのが一番分かりやすいです。

特に重要なのは次の点です。

- 自分側または相手側のNATが原因になる
- 接続テスト成功でも発生する
- 一部オンライン機能が使えても、対戦・合流だけ失敗することがある
- 実機NDSではIP固定、UPnP、DMZ、二重ルーター、CGNAT確認が重要
- melonDSではWindowsファイアウォールとPC側IP固定も重要
- ホットスポット/テザリングはCGNATやプライベートIPの影響で難しいことが多い
- VPNは条件つきで有効な場合があるが、普通のVPNでは直らないことも多い
